# Install the completed Windows UX candidate

Use the exact source commit supplied in the owner's handoff prompt, on `feat/windows-command-workbench`. Stop if no exact commit is supplied or the branch resolves to another commit. Do not use main, merge, rewrite history, publish a release, change visibility/license/signing, or bypass Windows security controls.

1. Reuse `C:\path\to\NerdSSHell` if present. Read AGENTS.md, README.md, SECURITY.md, UX-SECURITY-REVIEW.md and ACCEPTANCE-RESULTS.md. Check `git status` first; stop on uncommitted user changes. Do not stash/reset/discard them. Fetch origin, switch to the candidate branch and update with `git merge --ff-only origin/feat/windows-command-workbench`. Verify exact HEAD against the supplied commit; stop on mismatch.
2. Use Node 22 or newer and the committed lockfile: `npm ci --omit=optional`, `npm run check`, `npm test`, `npm run dist`, `npm run verify:package`, `node scripts/Verify-Notices.cjs`. All required checks must pass without weakening tests. `npm run verify:package` is the actual repository verification command. Record SHA-256 and Authenticode status of `dist\BetterSSH-0.1.0-x64-Setup.exe`. The candidate is an unsigned experimental build, with an unresolved build-dependency audit gate; it is not a trusted public release.
3. Identify the existing per-user BetterSSH installation and its actual Electron user-data directory. Make a local backup outside tracked source before upgrade, preserving settings, connections, host pins, workspace state, palettes, favorites and archives. Keep backups private; do not print or commit their contents. Do not change the application identifier or delete user data.
4. Before closing a running app, determine whether any LOCAL/Standard nonpersistent work or unsaved scratchpad is active. Stop and report active work; do not terminate it to install. If the state cannot be established safely, ask the owner to close normally after saving/finishing that work. Persistent sessions may detach normally. Never end mission sessions, kill remote tmux work or change global SSH/tmux/server configuration. Fully exit the app normally before replacing its files.
5. Run the exact newly built installer for the current user; require exit code 0. Preserve the current installation path (normally `%LOCALAPPDATA%\Programs\BetterSSH\BetterSSH.exe`). Compare installed `resources\app.asar` SHA-256 to the verified build. `scripts/Install-Windows.ps1 -NoLaunch` can build/install after the safety and backup checks; it reruns the build, so verify and compare the resulting artifact again. Do not use an uninstaller that deletes application data.
6. Launch the installed executable normally. Verify direct Rename/Disconnect/End Session controls, four dedicated Layout buttons (one window, two side by side, two stacked and four quadrants) with one highlighted active choice, collapsible Connections, Local PowerShell/admin switch, Scratchpad, Actions configuration and per-pane All Actions/favorites opening direct command review. Expanded rail says Local PowerShell; collapsed rail shows PS. New plain LOCAL consoles are numbered Local PowerShell 1, Local PowerShell 2, etc. Administrator requests native Windows consent and opens an embedded nonpersistent tab; confirm that separately with only harmless local commands. Verify Ctrl+Shift+P opens command review and Help includes placeholders. Existing customized colors should remain; fresh/default colors are lavender/dark gray. Focus mode/global Files/Full Screen buttons should be absent.
7. Use only an isolated test profile/loopback fixture or a new disposable console for command/transfer/end tests. Do not execute administrative actions, updates, sudo, service/Docker restarts, reboot/shutdown or production commands during installation validation. A harmless LOCAL console and scratchpad edit/collapse are sufficient smoke checks; native UAC and file-picker interaction remain separate manual acceptance. If native UI tools are unavailable, ask for a bounded visual observation and report that limitation rather than inventing a pass.

Report checkout path, exact source/installed commit, check/test counts, package verification, installer/executable paths and hashes, installer exit/result, settings preservation, confirmed UI features and anything requiring manual action. Do as much as possible directly; do not ask the owner to run commands you can run yourself.
