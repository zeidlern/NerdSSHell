# File SFTP and mixed SSH sessions

NerdSSHell provides a Local/Remote File SFTP browser per remote terminal and both Persistent and Standard sessions on one verified SSH connection. Browsing and file transfer preserve terminal ownership, host verification and session lifecycle.

## A File SFTP browser for each remote terminal pane

Every remote terminal view owns its optional SFTP browser. Click **File SFTP** in that terminal's header to expand/collapse it; there is no global Files toolbar button. In a two- or four-pane layout, any combination of browsers can be open. Multiple panes on the same server keep independent Local/Remote folders, selected files, text filters, hidden-file settings, docking choices and splitter sizes. Local PowerShell consoles do not have SFTP.

Choose **Right** or **Below** within each browser. Drag its divider or focus the divider and use the corresponding arrow keys. Below docking uses a compact two-column layout. Changing a browser's dock or size affects only the space inside its parent pane, not the overall terminal grid. Narrow panes constrain the browser size to retain terminal space; no automatic dock switching occurs. The terminal renderer resizes through its existing ResizeObserver path.

The browser stays with its terminal when tabs/panes are rearranged or hidden by a layout. State is retained for the lifetime of that terminal view in the app, not written to disk. Collapsing retains its folders, filters and size; expanding refreshes listings and revalidates selections. Closing a view disposes its browser and pending listing; re-opening creates a new browser. Cancelling one listing never cancels another pane's listing, even on the same server. On reconnect, file listing waits for its own terminal view to attach.

Each browser identifies its source session and actual saved connection: name, username, host and port. It does not follow a nested `ssh`, `sudo` or shell directory change. Use Home, Up, Refresh or an absolute remote path (or ~/). Double-click folders to navigate. Explicit link navigation displays the canonical target directory. The filter applies to the listed subset, not a recursive filesystem search. Copy path copies plain text and does not type or execute anything.

The **Local** panel starts within the current user's home folder. Home/Up/path navigation stays inside that pane's granted local root; **Browse** uses a native directory picker to grant another root to that pane. Both panels show names, sizes and modification times, with navigation, filtering and hidden-name controls. Local links are displayed but are not accepted as regular upload files.

Select a regular Local file and use **Local → Remote** to copy it into that pane's displayed Remote folder. Select a regular Remote file and use **Remote → Local** to copy it into the displayed Local folder, retaining the suggested safe basename. Drag a regular file between the Local/Remote panels of the same File SFTP pane for the same copy workflow. Cross-pane/stale-list drags are rejected; no drag implies move, delete or execution. External local-file drops upload into the displayed Remote folder; terminal-host drops retain the saved upload-directory behavior. The separate **Download…** control still offers a native Save dialog for a new local filename.

Transfers capture their original terminal key, browser, server connection, listed source and destination before awaiting confirmation/dialogs. A view/transport replacement or folder/selection change while approval is pending cancels the operation rather than redirecting it. The Local file/root is revalidated around approval and before submission. Once a transfer starts, collapsing the browser, switching tabs, changing layouts or closing just the terminal view does not cancel it. Disconnecting its SSH transport does. The transfer indicator identifies the connection and originating session while that view exists.

There is no implicit current-directory synchronization, injected `pwd`/`cd`, remote editing/deletion/renaming, execution preview or upload-on-save. Browsing uses separately scoped SFTP channels on the existing authenticated SSH transport, not another login or credential store. A server without SFTP reports an error in its browser without changing the terminal.

### File safety and limits

- Folder requests use handle-based reads, one current listing per pane-browser instance, a 20-second overall timeout, and at most 1,000 entries / approximately 256 KiB. Truncation is visible; the filter searches the listed subset only.
- At most 16 current listings and four transfers run across the app. A separate combined cap of 20 outstanding SFTP opens/live channels retains reservations after abort/timeout until actual channel or transport cleanup; a peer withholding callbacks cannot bypass the cap by repeated cancellation. The server can impose a lower channel limit. Each view has a unique browser-instance token, so an old cancellation cannot cancel a reopened view. Normal handle-based SFTP end-of-directory status is accepted; other errors propagate.
- Stale results are rejected by main-process connection/view identity, browser-instance ownership and request generation. Upload/download confirmations retain the original connection and directory even when selection changes. Disconnect aborts related operations. At most four transfers run concurrently.
- Remote paths and filenames are validated and rendered as text, never HTML. Returned names cannot traverse directories or become local filesystem paths.
- Downloads support regular files only, not directories or final symlinks. A native Save dialog chooses the local path. Reserved Windows basename characters are replaced in the default suggestion. Downloaded files are not opened or executed.
- Downloads stream through a private temporary directory next to the chosen destination, check advertised size and file metadata, and publish using exclusive hardlink creation. **Choose a new local filename: existing local files are not overwritten.** Unsupported filesystem publication fails closed. Cancellation/failure removes only this operation's owned temporary directory.
- Metadata/handle operations time out after 20 seconds; stalled downloads time out after 30 seconds. A post-open final-path check rejects persistent symlink replacement. SFTP v3 cannot provide portable atomic no-follow or identity binding; a swap restored between checks or same-size/time content replacement can evade detection. This is not a filesystem snapshot or a malicious-server authenticity guarantee.
- Uploads retain existing no-overwrite/explicit-replacement safeguards. A confirmed remote overwrite still has the documented race with another server-side writer. Folder upload, transfer resume and download-to-Explorer dragging are not included.
- Local listings have a 10-second timeout, at most 1,000 scanned entries / approximately 256 KiB, eight outstanding reads and 64 live browser grant records. A stalled filesystem read retains its reservation until actual cleanup. A native folder grant and the current pane's listed regular files constrain accepted Local selections; stale and detectable link/root/file substitutions fail closed. This is not an atomic filesystem snapshot or protection against every concurrent same-user filesystem change.

## Session types

Choose the session type in **New session**, rather than assigning one type to the entire connection. **Persistent session** is checked by default; uncheck it for a Standard SSH shell. Both can coexist on the same authenticated transport. Existing saved profile formats are compatible; legacy Standard-profile startup behavior is retained. There is no automatic downgrade of Persistent work.

Persistent sessions keep discovery, background survival, reattachment and recovery. New Persistent work explicitly enables required server support; any package installation offer requires approval. Connecting/discovery never launches a Persistent job. Closing a Persistent view or Disconnect leaves its remote work running. **End Session** asks for explicit confirmation bound to the session's stable identity. Ended sessions disappear immediately, including when the final Persistent server session has ended.

A Standard session opens an ordinary SSH PTY/shell channel through that connection's verified authentication; opening it does not install or enable Persistent support. The shared connection can separately perform read-only Persistent discovery or pane OS inspection. Legacy Standard profiles retain probe-free Persistent startup and their saved fresh-shell policy. Rename changes a Standard shell's local display label. Closing its tab/view, Disconnect, End Session or quitting asks for confirmation because its channel closes and work may stop; it cannot be reattached. App-owned confirmations place Cancel last/right and make it the default. Consent is revalidated against the original view, transport and live nonpersistent shell identities.

Network loss does not automatically launch replacement Standard shells or replay queued input. A shared Persistent connection may recover its transport and rediscover surviving Persistent work; a Standard shell still needs an explicit new-shell action. Closing a Standard shell leaves other channels and the SSH/SFTP connection available. There are at most 16 live Standard shells per connection (the server may impose a lower limit). SSH keepalives and terminal copy/paste/color controls are unchanged.

Incoming standard-shell output is paused/resumed around renderer acknowledgements, including stderr through natural exit, rather than relying on tmux snapshots. Its input queue preserves whole-message order and has a 256-message/2-MiB budget (1 MiB per paste). Closing/replacing/disconnecting invalidates pending input. A 20-second blocked-write timeout preserves the shell, discards unsubmitted input and reports partial-delivery uncertainty; new writes are blocked until the one submitted chunk (at most 32 KiB) drains. Bytes already submitted cannot be recalled. Local received-output archives remain optional and plaintext; there is no disconnected standard-session recorder.
