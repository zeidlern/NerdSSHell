## Concrete findings and fixes

Final native acceptance additionally found missing LOCAL ConPTY compatibility metadata in xterm, causing blank/misplaced screen rows on pane growth. LOCAL-only `windowsPty` compatibility fixes that display path; no remote input, host verification or IPC permission was loosened. The corrected interruption fixture requires fresh output, one successful reply within 20 seconds and absence of the interrupted sleep's completion sentinel. Actual clipboard and resize/interruption checks passed for both installed PowerShell versions; native UAC and clean-user acceptance remain unverified.

The focused security pass did **not establish a new privilege-escalation or cross-session execution/snooping exploit**. That statement is limited to the inspected paths and synthetic cases above.

Two concrete Actions UI races were found during the continuation and fixed with focused regressions:

1. Switching OS left previous action rows visible while templates loaded. Fast selection could operate on an old OS row under a new selector. The list now clears synchronously before the matching template request; the delayed-response regression verifies the correct OS owns the saved favorites.
2. A queued dialog close after Cancel could invalidate a freshly reopening configuration while its IPC response was pending. This matches the isolated native fixture's transient reopen failure. Draft disposal now occurs synchronously on Cancel/Save/Escape, and old close events do not cancel a new pending fetch. A deterministic queued-close regression passes; final packaged acceptance must be recorded separately after rebuilding this source.

The administrator helper review compared ConPTY startup structures and handle use with Microsoft's [MiniTerm and EchoCon samples](https://github.com/microsoft/terminal/tree/main/samples/ConPTY). Delayed output was traced by a disposable fixture to a synchronous duplex `NamedPipeClientStream`: its blocking frame read prevented concurrent output forwarding. The helper now opens that stream asynchronously. Teardown also makes console/input disposal once-only, keeps draining ConPTY after forwarding fails, catches ordinary native IO failures, bounds nonce-read time and independently watches the verified broker process so a blocked terminal input write does not prevent owned-job cleanup on broker exit. These fixes are source/fixture findings; they do not establish real elevation, alternate-account behavior or final installed acceptance.

The subsequent Windows PowerShell 5 compatibility correction preserves absolute-path PSReadLine import: prefer the `$PSHOME` bundle, then, only if absent on Windows PowerShell 5, the stock `ProgramFiles\WindowsPowerShell\Modules\PSReadLine` location. That fallback prefers a flat manifest or selects the highest numeric version while considering at most 32 immediate folders; reparse-point roots/version folders/manifests are refused. It does not search user `PSModulePath`, download/install modules or change profiles/policies. `SaveNothing` is applied before optional `-Colors`, so an older module's rejection of that parameter does not skip history disabling. The administrator bootstrap additionally verifies the loaded module location and SaveNothing setting, failing startup on unexpected loaded modules or history-setting failure. Ordinary bootstrap failure may leave an ordinary shell without this setup; no universal no-history guarantee follows. Program Files protection is an OS installation assumption, not a new signature/ACL audit or a defense against administrator/OS tampering. Candidate-specific runtime results belong in the acceptance record, not this source description.

## Security limits and remaining verification

- **The application window is a trusted shared workspace, not a permission boundary between its own panes.** Its legitimate renderer can access connected targets and deliberate sharing previews. A compromised renderer, same-user malware, a compromised operating system, malicious extensions outside this app, physical access or remote account compromise is not prevented by pane labels or input locking. Input locking is protection against accidental input, not an access-control system.
- **Reviewed/custom commands are not sandboxed.** They run with the selected account's permissions and can be destructive. Saving or highlighting a command does not certify safety. Keep the exact-code/native confirmation path and explicit disruptive built-in confirmation; do not add automatic recipe execution to OS detection or reconnection.
- **File revalidation does not make concurrent filesystems race-free.** Local source/directory identities are checked around consent, but later replacement between validation and actual stream opening remains possible. Parent junctions, hard links, network filesystems, same-user concurrent modifications and hostile remote file contents need their ordinary filesystem threat model. SFTP v3 lacks a portable atomic no-follow identity bind; detectable changes are refused, but undetected replacements remain possible. Explicit remote overwrite retains its documented concurrent-writer race.
- **UAC still requires real Windows acceptance.** The helper uses Windows elevation rather than an in-app credential mechanism. Real approval/cancellation, alternate-account credentials, secure-desktop/publisher behavior and closing the final installed elevated console remain acceptance gates. Ordinary consoles and no-elevation fixtures inherit their runner's token; neither establishes a medium-integrity test by itself. Fixed paths do not establish a trustworthy installed PowerShell binary. Launch environments and user/OS tampering remain outside the stated boundary.
- **The helper authenticates a launch, not an uncompromised user or publisher.** Its pipe DACL admits the current user, Administrators and SYSTEM, rejects remote clients and verifies expected spawned process IDs plus a fresh 32-byte nonce. The nonce appears in the encoded helper command line; it is not a secret against same-user/admin process inspection. Hashes bind the exact copied/loaded C# bytes before compilation and detect intervening changes; they are not signatures, installed-file provenance or protection from application/same-user/admin compromise. The terminal deliberately accepts user-approved elevated input, so it is not an elevated command sandbox. No generic filesystem RPC or persistent privileged service is added. The Job contains the newly created shell tree; it does not attach or terminate preexisting local or remote work.
- **Plaintext remains deliberate.** Saved custom actions and settings backups can contain command text; explicitly saved scratchpad files, copied previews, terminal archives and exports can contain secrets. There is no automatic redaction, encryption, secure erasure or background cloud transfer added by this UX work. Existing Windows profile permissions, backups, disk protection and the archive defaults remain relevant.
- **Do not equate tests with trusted distribution.** Existing dependency/advisory, unsigned installer, history/privacy, license, signing, native-dialog and clean Windows release gates remain. See `PUBLIC-RELEASE.md`, `SECURITY-REVIEW.md`, the final acceptance record and the candidate's actual dependency scan. This focused review changes none of those gates or their evidence.
