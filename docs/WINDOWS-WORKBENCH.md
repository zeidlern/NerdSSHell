# NerdSSHell sessions, Actions and command workbench

This guide describes the **v0.1.10** development interface.

Each terminal has an **Actions** dropdown and a horizontally scrollable row of **Favorite buttons** that insert the selected command and send Enter in that same terminal. **Preferences** contains their configuration. **Ctrl+Shift+P** opens a separate command-review workbench for commands you want to inspect and run in a new task console.

| Control | Behavior |
| --- | --- |
| A session's **Actions** or **Favorites** command | Inserts the configured command and Enter into that existing session. |
| The separate **Configure Favorites…** button | Opens Preferences directly to Configure Favorites, including offline. |
| **Preferences → Configure Actions / Configure Favorites** | Edits saved commands and favorite selections without executing them. |
| **Ctrl+Shift+P** command workbench | Stages and reviews commands; **Run in new console** asks for native confirmation before creating a task. |

Session title bars show a compact **REMOTE** badge with white lettering on red for SSH and a **LOCAL** badge with white lettering on green for PowerShell and Command Prompt. The badge describes the connection owned by NerdSSHell; a nested SSH command or another program inside the terminal does not change that connection's identity.

Use the dedicated Layout buttons **1**, **2 ↔**, **2 ↕** and **4** for one window, two side by side, two stacked or four quadrants. The active button has a pressed state; tooltips show **Ctrl+Alt+1/2/3/4**. Layout changes and divider resizing preserve each open view's identity. Focus mode is removed; fullscreen remains available through F11.

## Preferences and workspace controls

Preferences uses category navigation on the left and the selected settings on the right. Categories include **Copy & Paste**, **Terminal Colors**, **System Colors**, **Configure Actions**, **Configure Favorites**, **Notifications & Alerts**, and **Sessions & History**. One **Save** applies the settings together; **Cancel** discards the draft. Colors preview while editing and return to the saved appearance on Cancel. The Sessions & History values are defaults for new saved connections; existing connections keep their individual settings.

Layout controls remain on the main interface. **Scratchpad** is at the top of the sidebar, followed by the compact local-shell launchers. The collapsed sidebar's **Expand Sidebar** control has a distinct appearance. The redundant global bottom status/New Session bar has been removed; session creation remains available beside each connected server. Per-terminal controls such as Jump to live and Lock input remain attached to their own terminal.

## Local PowerShell and Command Prompt

Click **PowerShell** or **Command Prompt** above the saved connections to open an embedded local session. PowerShell 7 is preferred when installed, otherwise Windows PowerShell is used. The two shell families have independent numbering within the current app run: **PowerShell 1**, **PowerShell 2**, **Command Prompt 1**, and so on. Ordinary and administrator consoles of the same family share that sequence; cancelled/failed launches may leave gaps. Reviewed tasks retain separate Task names.

Local sessions appear in the sidebar's **Local sessions** list and use the same tabs, split layouts, colors, scrollback and clipboard behavior as SSH sessions. The review workbench also lists installed local shells; **Open PowerShell** or **Open Command Prompt** follows the selected target. **Open in folder…** uses a native folder picker for supported launches. Administrator Command Prompt starts in its elevated account's home directory; change directory inside that console rather than using the folder picker.

Discovery uses the fixed Windows PowerShell, Program Files PowerShell 7, and Windows System32 Command Prompt paths. Portable/per-user/custom PowerShell paths and WSL profiles are not implemented. PowerShell starts without loading profiles or changing execution policy. Command Prompt starts with `/d` to disable registry AutoRun commands and uses a process-local `$P$G` prompt. Ordinary launches do not request elevation. Run NerdSSHell itself as a normal user: ordinary child commands inherit the application's user privileges and environment.

**Local consoles are not persistent.** Closing or ending one terminates that shell and can stop its child processes. Local session controls offer **Rename** and **End Session**; they have no Disconnect option. Tab closure, ending a local session, and quitting with live nonpersistent consoles request confirmation. Consent is bound to the reviewed connections, transports and live shell identities; changed work requires a fresh review. No persistent local broker/service is installed, and no local console is silently restored after restart. Embedded local consoles do not have SFTP; Local filesystem panels belong to each remote pane's File SFTP browser.

For a new SSH session, **Persistent Session (tmux)** keeps the remote shell running if NerdSSHell disconnects or closes. Unchecking it creates a Standard SSH shell whose channel closure can stop work. This choice is made per remote session; local PowerShell and Command Prompt always remain nonpersistent.

Each local launcher has its own **Administrator** switch to its right. Its setting applies to newly launched sessions, and does not elevate an existing terminal. An administrator launch requests Windows UAC and opens an embedded elevated PowerShell or Command Prompt ConPTY in a new NerdSSHell tab. Launching an administrator console does not elevate NerdSSHell itself. The implementation handles UAC cancellation without retry and revalidates the captured destination/review after approval before sending reviewed startup text to that newly owned console. The app does not collect Windows passwords or change UAC/security controls. Real UAC approval/cancellation and alternate-account credentials still require acceptance against the final installed candidate.

`src/elevated-pty.cjs` starts a fixed broker; `src/elevated-console.cs` creates the short-lived Windows-elevated helper. Only the supported Windows PowerShell, PowerShell 7 and Command Prompt IDs and their fixed installation paths are allowed. Exact loaded C# bytes are SHA-256 checked before compilation in both processes; that proves byte consistency, not signing or publisher identity. The protected, remote-rejected pipe checks both spawned process IDs and a fresh 32-byte nonce. Only bounded terminal input, resize and close frames cross the boundary; it exposes no generic filesystem RPC. The helper creates its shell suspended, assigns it to its own kill-on-close Job, then resumes it. Pipe closure and broker-process exit dispose that owned console/job, without attaching existing local or remote work. Its output continues draining during teardown. These mechanisms do not isolate the console from same-user malware, other administrators, SYSTEM or a compromised application/OS; the nonce is present in the helper's encoded process arguments.

The process-local PSReadLine bootstrap first considers the absolute `$PSHOME/Modules/PSReadLine/PSReadLine.psd1` path. For Windows PowerShell 5 only, if that manifest is absent, it also supports the stock module under the fixed, normally protected `ProgramFiles\WindowsPowerShell\Modules\PSReadLine` folder. A flat manifest there is preferred; otherwise version discovery is limited to 32 immediate subfolders, with the highest numeric version containing a manifest selected. Exceeding that limit rejects the setup. Reparse-point module roots, version folders and manifest files are rejected. Import uses the selected absolute path, not a module-name search through user `PSModulePath`, Downloads or user-installed modules. No module installation, profile edit or execution-policy change occurs.

Administrator consoles use the same pinned ConPTY/OpenConsole pair as ordinary consoles. Before elevation, the broker checks the fixed pair's bounded bytes; the authenticated helper checks its own reads again. The helper creates a fresh `ProgramFiles\NerdSSHell-ConPTY-<random-id>` directory and both native files with explicit administrator ownership and administrator/System-only protected permissions. It holds the paths stable, rejects reparse/ambiguous paths, loads only the matching DLL through a restricted absolute path, and gives the console-host process a protected working directory and System32-only search path. The interactive shell retains its original environment and home directory. Normal teardown drains output, closes the owned console and removes only those staged files and their directory. A genuinely unelevated test fixture uses an explicitly separate current-user/SYSTEM Temp stage; an already elevated fixture exercises the production staging branch without requesting UAC.

After importing, the bootstrap sets `HistorySaveStyle SaveNothing` before attempting optional `-Colors`. Older PSReadLine releases may reject `-Colors`; that rejection leaves the earlier no-history setting intact and retains the shell's ordinary input colors. An absent supported module means this setup is unavailable. The administrator bootstrap rejects unexpected already-loaded PSReadLine locations and failures to establish/verify SaveNothing, rather than continuing with that module's default history behavior. This is interactive PowerShell input coloring, not arbitrary Python/code output. Other logging, process arguments or deliberate later shell configuration can still expose commands; this setting is not a confidentiality guarantee.

This preview packages the x64 ConPTY components for Windows x64. It is not a native ARM64 or iPad build.

## Session Actions and Favorites

Selecting an enabled command in a session's **Actions** dropdown or clicking a **Favorite button** executes it there. The command and Enter share one ordered input event, using the terminal's negotiated bracketed-paste behavior where enabled. The foreground program receives that input just as if you pasted it manually; the session keeps its current working directory, environment, account and shell state. Use the control at the prompt where you intend to enter the command.

A service or container recipe that needs a name shows a small inline field in the same terminal. Enter the exact name and choose **Run**, or **Cancel** to discard it. Regular configured commands need no extra review or configuration screen. This direct behavior also applies to disruptive built-ins such as updates, restart and shutdown; any operating-system, sudo or package-manager questions appear in the terminal. The separate workbench confirmation rules below apply only when using the workbench.

Commands remain bound to the invoking pane even if another session is selected. Main resolves the saved action ID for that target's actual OS and shell, checks its connection/view/session identity and input lock, then uses the existing terminal input queue. A replaced session, disconnected view or old snapshot invalidates its menu target; pending parameter entry is discarded on recovery. Commands are not replayed after reconnect. Input already accepted by a transport cannot be recalled.

Each attached pane automatically attempts bounded read-only OS/tool inspection when its action bar lacks an identified OS. **Detect system again** retries the inspection. The review workbench also offers **Detect system** explicitly. Inspection uses a separate SSH channel and does not paste commands into the visible terminal, install anything or elevate privileges. Unsupported or unidentified systems do not get guessed update commands.

To configure recipes, open **Preferences → Configure Actions** and choose an operating system. **Preferences → Configure Favorites** has its own operating-system selector and checkboxes for up to **32 favorites per OS**. Favorites appear as buttons in saved order when applicable to that session's OS and shell. Commands whose tools are unavailable remain disabled with a reason in their tooltip. The row scrolls horizontally, and keyboard focus brings each button into view. **Configure Favorites…** is a separate button that stays reachable offline. Existing saved favorites are preserved. Changes remain staged until the common Preferences **Save**; Cancel discards them.

Windows configuration also offers a **Windows shell** selector for **PowerShell** or **Command Prompt**. Existing Windows custom actions retain their PowerShell meaning. New Command Prompt custom actions store that shell explicitly, so PowerShell text is not silently pasted into CMD. Favorite IDs remain shared within the Windows category's 32-item limit, with each terminal showing only its compatible entries.

Built-ins can be previewed without contacting a host; the editor's OS choice is not system detection. Edit a built-in preview or create a new named command, choose **Keep custom action**, then the common Preferences **Save**. The first step stages the command in memory; the second persists it with the other Preferences changes. Saving with unstaged editor changes is rejected. Replace any example service/container name in a copied recipe with the intended value before saving it. Up to 64 custom actions are supported, with an 8 KiB UTF-8 command limit each. A generic Linux custom action also applies to the supported Linux distribution categories. Editing a built-in creates a separate custom action and does not alter its built-in safeguards. Saved recipes are plaintext in user settings and are not certified safe.

There are 18 catalog entries, with availability based on the target: system information, disk space, memory, processes, addresses, listening ports, update checks/install, sudo validation, service listing/status/logs/restart, container listing/logs/restart, restart and shutdown. Not all entries apply to every OS.

Capability detection is bounded and read-only, whether initiated by the pane or explicitly retried. A systemctl binary alone does not establish an active systemd manager; journal actions independently require journalctl. Conflicting system identities fail closed. Reinspection clears old capabilities before probing, including when the probe fails. Known distribution IDs choose their expected package manager; ambiguous alternatives and rpm-ostree/bootc tooling are not guessed.

APT update checks use current cached metadata; the upgrade action refreshes first. DNF code 100 means updates exist. Arch checks require checkupdates, whose code 2 means no updates; installing upgrades uses full `pacman -Syu`. macOS uses softwareupdate where available. Local Windows update checking opens Windows Update settings rather than silently installing anything. Installing remote updates is disruptive. A session menu submits the command directly in that session; when using the review workbench instead, type the exact hostname and review the native confirmation. Package prompts remain interactive, no unconditional `-y` or `--noconfirm` is added, and NerdSSHell does not request a reboot. Package scripts and system policy may still restart services or interrupt SSH.

Service inspection does not silently elevate or follow logs forever. Service listing covers loaded units rather than every installed unit file. A nonzero service-status exit can mean inactive/failed/missing, not merely a failed query. Docker operations use the account’s configured context, which can address another computer; verify that context before a restart. The SSH target label does not identify a remote Docker daemon. PowerShell memory/disk fields have explicit MiB/GiB labels; CPUSeconds is cumulative CPU time, not live utilization. Command Prompt uses native equivalents: `systeminfo`, `dir`, `tasklist`, `ipconfig`, `netstat` and `sc query`. Its `dir` recipe reports the current directory and free bytes on that drive, rather than PowerShell's all-drive table; `tasklist` lists process memory rather than ranking current CPU usage.

**sudo -v is not global Windows elevation.** From a session menu it runs in the current terminal. Its credential cache depends on server policy and may be limited to that terminal; continue administrative work there when appropriate. Running the same recipe through the review workbench creates a new console, whose cache can be separate. Another console may ask again. There is no guessed expiry timer, blanket sudo shell, password database or sudoers modification.

## Separate command-review workbench and commands from chat

Open **Ctrl+Shift+P** when you want the workbench's searchable catalog, editable command review, imported chat blocks, or a new task console. Its catalog uses the same saved configuration and OS/shell availability as the session menus, but selecting a recipe stages it in the workbench editor. The star shortcut opens Preferences directly to Configure Favorites.

Search common intentions such as disk, memory, updates, services or logs in the review workbench. Windows terms such as Task Manager, Event Viewer, ipconfig and drive properties are also searchable. Unavailable actions show a visible reason rather than only a disabled control. Enter an exact service/container name before choosing an action that requires one. The selected command appears in the editor with its explanation; selecting a template does not run it.

Paste code directly into the editor, or expand **Import code blocks from chat** and select one fenced block. Prose and copied shell prompts are not automatically stripped. Blocks are never concatenated, translated or automatically executed. Review Bash-specific syntax carefully: remote tasks use POSIX `/bin/sh`, not necessarily your usual interactive shell. An explicit bash invocation belongs in the reviewed command when needed.

Choose **Review command** to see the exact code, target, persistence limitations and advisory warnings. Editing code or changing targets invalidates the old approval. Built-in disruptive actions require typing the exact remote hostname. **Run in new console** then presents a native confirmation dialog. Reviews expire after five minutes. Expiry and cancellation are checked again after native confirmation and immediately before submitting a new task. Disconnecting invalidates the selected review, even during confirmation; reconnecting requires a fresh review. The same approval cannot be reused. Cancellation before submission starts no task; cancellation or network loss after submission cannot undo work already sent to the original target.

Execution creates a NEW task console on the captured connection. It never types into an existing coding agent/editor. The task begins in the account's default directory, not another pane's current directory or SFTP folder. Include the necessary `cd` explicitly. Switching focus or reconnecting cannot redirect an approved task to another machine. Remote Persistent tasks use new server-side sessions; Standard tasks, local PowerShell and Command Prompt tasks are nonpersistent. The task console remains available to inspect output and continue manually unless the command or system closes it.

When the workbench is opened for a specific pane, its new task preserves that source's Persistent/Standard provider as well as its host, view and session identity. Choosing a Standard source on a mixed connection does not silently turn the reviewed task into Persistent work. A changed/closed/replaced source requires a fresh review. This task-creation behavior is separate from the existing-session Actions dropdown and Favorite buttons. Native app confirmations put Cancel last/right and make it the default.

Reviewed CMD text uses interactive Command Prompt syntax. It is sent only to the newly owned CMD console after readiness and a final ownership/review check, with newline handling equivalent to terminal paste. This supports multiline interactive commands; it does not turn a pasted batch file containing labels, `goto` or batch-only `for %%i` syntax into an executed `.cmd` file. Normal and administrator CMD launches disable AutoRun, and startup text is not interpolated into CMD's process arguments.

Pattern warnings are not proof of safety. A custom command can be destructive even when it is not recognized. All commands retain the selected account's actual permissions. This is a review workflow, not a command sandbox or AI security scanner.

## Input locks and sharing

**Lock input** blocks typing, paste, Actions and Favorites at the backend for that view and invalidates its unsent queued input. Copying and reading continue. Already submitted bytes cannot be undone. The lock does not revoke server privileges or lock other clients attached to the same session.

**Review terminal output for sharing** collects at most the last 200 terminal rows and 128 KiB of UTF-8 text. It preserves spaces across soft wraps, excludes empty wide-character padding, and labels the buffer, included rows/bytes, omitted older rows and a mid-wrapped starting line. It is an excerpt, not a complete transcript or a guaranteed command-output boundary. **Connection diagnostics** captures at most 64 connection summaries and 100 bounded events; metadata fields are limited to 256 characters or less. It identifies itself as an application snapshot, not a server-health scan. It does not collect command bodies, terminal output, keys, passwords, environment variables or arbitrary remote errors. Controls and direction overrides are displayed with visible U+ labels; this is not automatic secret redaction.

Both open an editable preview before **Copy reviewed text**. Opening a preview never copies it automatically. Closing or cancelling clears the preview immediately and invalidates pending results; a late response cannot replace a newer edited preview. Copy uses only the reviewed text, with a 512 KiB limit including headers. Hostnames, usernames and output may be sensitive. Redact before copying; nothing is sent to a cloud service automatically. Copying can place material in Windows clipboard history/sync, according to Windows settings.

## Waiting for input

**Preferences → Notifications & Alerts** controls waiting-for-input detection, audio, Windows notifications and visual session indicators independently. All four are enabled by default. Each session has its own waiting state. A background terminal that presents a supported question can show **WAITING**, highlight its session entry, play a short sound and produce a Windows notification; audio and desktop alerts stay quiet for the active terminal in the focused app.

Detection uses prompt evidence rather than ordinary idle time. It can miss unfamiliar application prompts, so it is an aid rather than a guarantee that every Hermes or Codex question will be recognized. A new waiting event normally alerts once; acknowledged prompts and resumed work clear the attention state. Notification clicks select a still-current session and never submit an answer. Windows notification policy and Do Not Disturb can affect native delivery. See [Waiting for input](WAITING-FOR-INPUT.md) for supported signals, lifecycle behavior and exact acceptance limits.

## Scratchpad

The **Scratchpad** button at the top of the sidebar opens one shared full-height editing panel. Drag its divider or use its arrow keys to resize; Collapse hides it without deleting its notes. Auto/plain/Markdown/code/PowerShell preview modes produce inert text spans, not executable HTML or Markdown links/images. **Bold** inserts Markdown markers into the plain text; this is a bounded lexical preview, not a full rich-text editor.

Notes remain in memory until explicit **Save As**, supporting UTF-8 text up to 1 MiB without NUL characters. Choose a new filename: the app does not overwrite an existing file, even if one appears after the Save dialog. **Open** loads a deliberately selected bounded UTF-8 file. Replacing unsaved notes and quitting require confirmation. Edits made while Open/Save or quit confirmation is pending are preserved and may require renewed review. Files remain plaintext; no automatic sync/cloud transfer or secret persistence is provided. **Copy** deliberately uses the Windows clipboard, whose history/sync may retain the text.

## Data and implementation limits

Favorite IDs and explicitly saved custom actions are stored in user settings. Unsubmitted review code/chat text and unsaved scratchpad notes live in the window's memory until cleared or the process exits; JavaScript and the OS do not guarantee secure erasure. Output may be recorded by an existing explicitly enabled remote profile archive. Commands may appear in process arguments, server logging, shell history or visible output. PowerShell EncodedCommand is encoding, NOT encryption; do not paste secrets expecting them to be hidden.

Reviewed remote scripts are limited to 32 KiB, local reviewed scripts to 8 KiB, and local pasted input to 64 KiB per submission with a bounded rate. There are limits on concurrent launches, reviews and platform probes. Exhausted limits fail explicitly rather than queueing unlimited future operations.

Native Windows acceptance, OS-specific administrative actions and multi-monitor/IME/accessibility behavior must be assessed against the exact candidate. The full **0.1.8 packaged UI passed 160 checks**, including all three default resize/editing cycles for both Windows PowerShell 5 and PowerShell 7, without disabling prediction. This establishes the ordinary-console correction for the earlier before-Enter placement failure. The separate system-ConPTY administrator-provider fixture still failed; version 0.1.9 changes that provider and requires its own native validation. See [ACCEPTANCE-RESULTS.md](ACCEPTANCE-RESULTS.md) for exact revisions and results, and [ASTRA-HANDOFF-2026-10-03.md](ASTRA-HANDOFF-2026-10-03.md) for the historical report. The earlier PR #9 evidence applies to its pinned revision, not automatically to later changes. Synthetic transport tests and a no-elevation helper fixture do not establish native UAC acceptance: the fixture inherits its runner's token. Native UAC approval/cancellation, alternate-account credentials and file-picker interaction remain acceptance work; no success is claimed here. No real user's server was used to test reboot, shutdown, updates or privileged actions. Those recipes are reviewed/generated/tested as text; they are not certified across every Linux distribution or macOS release.

The existing unsigned-preview, privacy/history, licensing and independent-security-review gates still apply. This feature does not make the product production-certified.
