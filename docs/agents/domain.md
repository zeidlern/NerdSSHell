# Domain docs

NerdSSHell uses a single-context layout. The root `GLOSSARY.md` holds terms and `docs/adr/` holds architecture decision records (ADRs).

Before exploring a domain area, read `GLOSSARY.md` and the ADRs that apply when those files exist. Use [ARCHITECTURE.md](../ARCHITECTURE.md) and [IDENTITY-COMPATIBILITY.md](../IDENTITY-COMPATIBILITY.md) for established terminology and design constraints. Follow the initial reading requirements in [AGENTS.md](../../AGENTS.md).

Use established terms consistently in tickets, proposals and tests. Capture new terms or decisions through `domain-modeling` as they are resolved. If a proposal would change an existing ADR, name the decision and explain why to revisit it.
